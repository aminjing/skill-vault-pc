# 调用协议（agent 执行规则 · 唯一事实源）

本文件是 Hermes agent 操作本技能仓的**唯一事实源**。仓库内其他说明有冲突时，以本文件为准。

## 一、入库流程（新增 skill 时执行）

1. **获取来源**
   - 用户提供：用户给出下载好的 skill 项目路径或 GitHub 链接
   - agent 自寻：用户在聊天中提出需求（如"找个做瑞士风格 PPT 的 skill"）时，agent 在 GitHub 搜索合适的 skill 项目
2. **通读原项目**：完整阅读其 README / SKILL.md / 代码结构，弄清：做什么、怎么触发、依赖什么（API key / 工具 / 运行时）、许可协议
3. **向用户汇报**（必做，在入库前）：说明这个 skill 是做什么用的、适用场景、有无坑；用户确认后才打包
4. **打包入库**，每个 skill 一个目录 `skills/<skill-name>/`：
   - `SKILL.md`：打包后的 skill 定义，结构见下文
   - `SOURCE.md`：来源元数据，结构见下文
   - 原项目关键文件：按需拷贝（脚本、模板、参考文档），不拷贝体积大的二进制/模型文件，只记录获取方式
5. **更新索引**：在 `skills/README.md` 表格追加一行
6. **提交**：独立 commit，message 格式：`skill: <skill-name> — <一句话用途> (来源: <repo>)`

### SKILL.md 结构

```markdown
# <Skill 名称>

## 用途
（这个 skill 做什么，一句话 + 一段展开）

## 触发场景
（用户说什么话 / 做什么任务时应该想到用它）

## 执行步骤
1. ...
2. ...

## 依赖
（需要什么工具 / API / 环境）

## 示例
（输入 → 输出示例）
```

### SOURCE.md 结构

```markdown
# 来源

- 原仓库: <URL>
- 作者: <author>
- 许可: <license>
- 入库日期: <YYYY-MM-DD>
- 归档 commit: <本仓库 commit hash>
- 原项目版本/commit: <如有>
- 备注: <改了什么 / 裁剪了什么>
```

## 二、调用流程（用户提出需求时执行）

用户说"做个 PPT / 画个图 / 写个 X"这类**创作或执行类需求**时：

1. **先列清单**：查看 `skills/README.md` 索引，把仓内相关（及全部）skill 列给用户看，每个附一句用途
2. **主动询问需求**：在动手前问清楚关键决策，典型问题：
   - 风格：如"PPT 要什么风格？瑞士风格 / 极简 / 商务 / 科技……"
   - 范围、受众、输出格式
   - 如果用户点名某个 skill（"用瑞士风格那个"），直接读取该 skill 的 `SKILL.md` 执行
3. **执行**：严格按 `SKILL.md` 的步骤做；步骤里引用的脚本/模板用 `skills/<name>/` 下的打包文件
4. **交付**：产物给用户，附上所用 skill 的名称与来源

## 三、维护规则

- 工作目录：`Z:\chang-yong\.worktrees\skill`（skill 分支 worktree）
- 一个 skill 一个 commit；不留未提交的半成品
- 许可不明的项目不入库；需要 API key 的 skill 在 SKILL.md 里注明 key 放哪
- 用户对某 skill 提了改进意见 → 直接改 `SKILL.md` 并新 commit（message: `skill: <name> — 更新: <改了什么>`）
- 技能仓本身的行为规则（何时列清单、何时问风格）与本文件冲突时，以用户最新指示为准
